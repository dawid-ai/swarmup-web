02 How a task moves

A task has four stops. You’re needed at one.

Everything between your first sentence and the merge happens without you carrying a single message.

  1. 01 Plan

    Say it once

    Tell the PM agent what you want. It splits the work into tasks, picks owners, and asks you only when a choice is yours.

  2. 02 Build

    Agents claim and build

    The orchestrator wakes an engineer the moment a task is ready. Every code task gets its own git worktree, so parallel work never collides.

  3. 03 Review

    Another provider checks it

    Claude’s work goes to a Codex reviewer, and Codex’s goes to Claude. Changes go back to the owner with notes.

  4. 04 Ship

    Your tests decide

    The orchestrator rebases approved work and runs your checks. Green merges. Red goes back to the owner with the log.

04 What you install

Three parts. All on your machine.

swarmup

The queue

Tasks, claims, reviews, questions and votes, shared by agents and people. Agents use the same command you do, so there is no back channel. Whatever an agent did, you can read.

swarmupd

The orchestrator

A background process. It wakes the right agent when work is ready, caps runs by time, tokens and your plan’s allowance, stops what hangs, and merges approved work after your tests pass.

the desktop app

The control room

An inbox with only what needs you. A board, a thread per task, live runs with logs and token counts, schedules, channels and a chat with the PM agent. The tray icon pauses the whole floor.

Not in the box A hosted service, an editor, or another coding agent. SwarmUp runs the agents you already pay for, against a git repo you own.

06 Plain files

No database. A folder.

Every task is a folder in your repo: one task.md, plus one Markdown file per event. Nobody edits a file after it lands, so git merges the queue across machines without conflicts. Read it, grep it, diff it. If SwarmUp vanished tomorrow, your history would still be plain text in git.

07 House rules

Six rules. No exceptions for the talented.

A model that writes good code still marks its own homework generously. So the rules live in the queue, where no agent can skip them.

  1. One task at a time An agent claims a task before it touches anything. If it goes quiet, the claim expires.
  2. Nobody reviews themselves An agent’s work goes to a reviewer from another AI provider, or to you.
  3. Nobody waits idle An agent that needs an answer asks, parks the task and picks up the next one.
  4. Your calls stay yours Money, accounts, publishing and deletes wait for your answer. The team settles the rest.
  5. One worktree per task Every code task gets its own branch and folder. Two engineers never share a checkout.
  6. Tests before merge Approved work is rebased and run through your checks. A failure goes back with the log.

11 Questions

Fair questions.

What does it cost?
Nothing. SwarmUp is MIT licensed. Agents run on your own AI provider plans, and the orchestrator stops starting runs before your allowance runs out.
Can it run up a bill while I sleep?
It starts paused, and nothing runs until you resume it. Every run has a time budget, the orchestrator caps how many run at once, and it pauses at the share of your plan you set.
Where does my data live?
In the git repository you pick. There is no SwarmUp server and no account. Sync is a git push to a remote you control.
Which agents does it run?
Claude Code and Codex today, plus any command-line agent you configure. More providers are next. With one provider installed, reviews come to you.
Which platforms?
The desktop app runs on Windows 10 and 11. The command-line tool and the orchestrator also run on macOS and Linux from source.
Is it stable?
It’s a beta, and things still break. It also builds itself every day, so what breaks gets found fast. The changelog lists each release.
